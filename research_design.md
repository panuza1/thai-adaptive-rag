# Research design

Status: initial protocol, development pilot only. No held-out conclusion is authorized by development results.

## Systems and invariants

B1 uses normalized multilingual E5 small cosine scores. B2 fuses the top 20 BM25 and dense candidates using RRF with constant 60, retaining 20. B3 reranks those 20 candidates with the fixed multilingual cross encoder. P1 first performs dense retrieval, then selects A/B/C. Dense work is reused inside the same request; there is no hidden free confidence probe. Return five chunks for every system. Same corpus, normalization, model revisions and generator prompt apply to all arms.

Router: tokenize query with PyThaiNLP newmm; mark exact-token proxy when digits, Latin strings or quotation marks occur; compute dense top-1 minus top-2 cosine margin. Select C if token length >=24 or margin <0.02, otherwise B if exact-token proxy, otherwise A. These are provisional engineering thresholds, not trained or validated findings. NER and semantic ambiguity are not implemented; margin is a proxy, not calibrated correctness probability.

## Data and leakage controls

Use upstream iApp SQuAD **training partition only**, pinned to commit 644a29c59bac62d5b15b9e9b06c55bba00708eca. Final split protocol v2 first joins identical normalized article titles or contexts into connected components, then uses the lexicographically smallest context SHA256 in each component: first eight hex digits modulo ten; 0–5 development, 6–7 validation, 8–9 test. Assert each source article has a single context. Identical normalized contexts and same-title variants share a split. Globally deduplicate normalized questions. Audit near-duplicate articles before final test; exact grouping alone cannot eliminate semantic duplicates.

Corpus includes all source contexts across splits: this is a fixed open-book retrieval corpus, not training on test answers. Never insert questions or answers into corpus text. Chunk raw context into 600-character windows with 100-character overlap; validate raw answer offsets before normalizing chunk text. Gold evidence comprises chunks fully containing an annotated answer span in its source context. This is **derived span relevance**, not exhaustive human relevance: semantically equivalent unannotated passages can be false negatives. Log exclusions; do not silently call the subset the complete iApp benchmark.

Current development pilot samples 30 questions deterministically by seeded hash but retrieves against the entire processed corpus. Test queries remain unmeasured. Use full development for threshold exploration, validation for selection, then freeze code/config hashes and evaluate the entire test once. Candidate grid: lengths {16,24,32}, margins {0,0.01,0.02,0.04}. Prefer lowest measured cost satisfying development quality constraint; confirm on validation. If none qualify, report failure, retaining fixed baselines.

MIRACL Thai is a planned secondary retrieval benchmark; full corpus, original relevance judgments and held-out evaluation required. No MIRACL answer-generation claims. Check E5 training exposure first.

## Metrics and inference

Recall@5 = retrieved gold chunks / all annotated relevant chunks; MRR@5 is reciprocal first relevant rank truncated at five; nDCG@5 uses binary gains. Overlapping chunks create multiple gold items: report source-document metrics in a follow-up sensitivity analysis before publication.

Answer correctness: strict normalized exact match plus blinded human semantic correctness. Faithfulness: supported atomic factual claims / all factual claims. Unsupported claim rate: unsupported claims / all claims; distinguish contradicted from insufficient-evidence claims. Hallucination rate: fraction of non-abstaining responses containing at least one unsupported claim. Empty-claim answers have undefined claim faithfulness, not perfect faithfulness. Abstention accuracy requires labeled answerable and unanswerable cases; source iApp alone is insufficient. Construct and independently validate unanswerable cases before measuring it.

Two Thai-proficient annotators independently label shuffled anonymous outputs using retrieved evidence and reference answers, adjudicate disagreements and report agreement. Annotation templates are generated by the generation runner; empty labels are pending, never zeros. Automatic EM cannot validate hallucination. Ragas is a possible secondary judge only after agreement calibration and explicit API budget approval.

Measure warm online wall latency, CPU process time, router overhead and reranked-pair counts; separate index/model setup. Fixed CPU threads, randomized system order, no concurrent benchmarks; repeat final timing at least three times and record p50/p95. Generation records model input/output tokens and end-to-end latency. Local API bill is zero, not zero compute/energy cost. Do not infer dollar savings from latency. Current harness measures CPU; GPU synchronization would be needed for rigorous GPU timing.

Use paired article-cluster bootstrap (2,000 replicates, seed 2027), resampling complete groups and keeping system pairs. Report mean deltas and 95% intervals; exploratory multiple comparisons are not confirmatory significance tests. For non-inferiority require lower confidence bound of correctness difference > -0.03, with prespecified annotation and sufficient sample size. Pilot cannot establish this. Estimate power/sample needs from development before freezing final evaluation.

## Ablations and learning gate

Disable complexity, exact-token proxy or confidence one at a time. No-hybrid routes B to A and reranks dense candidates for C. No-reranking maps C to B. Keep thresholds fixed in primary ablations; optionally retune on development only in a separately labeled analysis. Record strategy proportions, per-query best baseline, routing regret and failure categories. Oracle uses labels and is an upper-bound diagnostic, never deployable router input.

Only investigate a shallow decision tree or logistic router if development oracle gains exceed noise and route labels vary sufficiently. Generate labels by cheapest strategy satisfying per-query quality tolerance, account for measurement noise, train only on development, select on validation. No learned model is justified yet.

## Remaining validity gates

Complete full-text literature audit; near-duplicate audit; answer-context truncation audit; reranker Thai suitability; frozen calibration; independent final run; double annotation; timing repetition and hardware isolation. Negative results remain publishable evidence. Do not submit this pilot as a completed experimental study.

### Annotation execution

`src.score_answers` consumes adjudicated `generation.jsonl`-format labels and leaves missing metrics null. It reports pooled (micro) claim faithfulness and unsupported-claim rate. Its hallucination denominator is **responses with at least one factual claim**, explicitly named in the output; this differs from the planned non-abstaining-response denominator when a non-abstaining response has no factual claims. Reconcile and freeze this denominator after annotation protocol review, before confirmatory testing. Use `python -m src.score_answers path/to/adjudicated.jsonl`. Keep raw independent annotations separately; the script is not an annotator or agreement calculator.

### Updated dataset shortlist

NitiBench (https://arxiv.org/abs/2502.10868) and the Thai Royal Gazette evidence dataset (https://huggingface.co/datasets/VISAI-AI/thai-gazette-evidence-retrieval, described in https://aclanthology.org/2026.nllp-1.19/) are credible secondary Thai candidates discovered during the updated search. The latter provides stronger evidence-span supervision but uses synthetic question construction. Do not silently replace iApp midway through the pilot; first inspect licenses, schemas, answer availability and split rules, then freeze a separate domain-generalization experiment. These additions strengthen the shortlist without treating uninspected releases as downloaded data.

Split audit update: v1 exact-context grouping missed two same-title near-duplicate pairs. v2 repairs these before validation/test use. Six query assignments change, yielding 3,360 development / 1,133 validation / 1,174 test queries. The 30 selected development pilot records are identical across v1/v2. Three additional high-similarity cross-split pairs concern distinct entities with templated text; retain as a generalization limitation and consider conservative family grouping in a sensitivity analysis.

Chunk identity uses the hash of the **raw** source text plus raw offset, while split grouping uses normalized titles/contexts. This prevents distinct raw whitespace variants from overwriting each other at a shared normalized hash/offset. The corrected corpus has 3,223 chunks. Earlier 3,221-chunk lexical outputs are preserved as v1 engineering evidence only.

Use the unchanged provisional thresholds (length 24, margin 0.02), all five ablations and three randomized-order retrieval repeats. Report article-cluster uncertainty and descriptive comparisons; do not infer general superiority from a small sample. Generator is pinned in `experiments/generator.json`.
